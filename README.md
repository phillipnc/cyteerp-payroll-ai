# CyteERP Payroll AI

Standalone ERPNext/Frappe v16 app for Africa-wide payroll intelligence.

The app separates three concerns:

1. **Deterministic payroll calculations**: tax and statutory rules are versioned
   country packs, never generated by a language model.
2. **Payroll intelligence**: explanations, variance checks and anomaly detection
   are safe, read-only services over approved payroll results.
3. **Human approvals**: posting payroll, changing salary data and submitting
   statutory returns remain controlled ERPNext actions.

The first release ships the shared engine and a 54-country catalogue. Country
packs are deliberately marked `scaffold` until a local compliance owner
provides verified rules and effective dates. This prevents the application from
inventing rates or presenting an unreviewed calculation as legal advice.

## Features

- One shared calculation engine using `Decimal` arithmetic.
- Versioned country-pack metadata for all 54 UN member states in Africa.
- Configurable progressive tax bands, deductions and employer contributions.
- Calculation traces that explain every result and preserve the rule-set version.
- Deterministic anomaly checks for payroll changes and master-data quality.
- AI-ready explanation service with an optional OpenAI-compatible adapter.
- Frappe whitelisted APIs for payroll officers and employee self-service.
- ERPNext v16 DocType for country-pack governance and provider configuration.
- Pure-Python tests that run without a Frappe bench.

## Install

From a Frappe bench:

```bash
bench get-app https://github.com/phillipnc/cyteerp-payroll-ai.git
bench --site <site> install-app cyteerp_payroll_ai
bench --site <site> migrate
```

The app does not modify ERPNext core payroll. It can calculate a supplied
payroll payload, explain an existing Salary Slip, and identify exceptions before
an authorised user submits Payroll Entry.

## API examples

The calculation API accepts a JSON payload:

```json
{
  "country": "ZM",
  "rule_set": "demo-progressive-2026",
  "currency": "ZMW",
  "gross_earnings": 18500,
  "taxable_earnings": 18500,
  "employee_deductions": [
    {"code": "pension", "amount": 500}
  ],
  "employer_contributions": [
    {"code": "napsa", "amount": 500}
  ],
  "tax_bands": [
    {"up_to": 3000, "rate": 0},
    {"up_to": 8000, "rate": 0.20},
    {"up_to": null, "rate": 0.30}
  ]
}
```

The response includes gross pay, tax, deductions, net pay, employer cost and a
calculation trace. In production, tax bands and contribution rules should be
loaded from an approved country pack rather than sent by the client.

## Country-pack governance

Every statutory rule must carry:

- country and currency;
- effective and expiry dates;
- source authority and source reference;
- approval status and approving user;
- a unique rule-set version;
- golden payroll test cases.

The app intentionally includes country metadata for all 54 countries, but does
not claim that every country is production-ready. Use the settings DocType to
record readiness and the approved rule-set reference as local compliance work is
completed.

## AI safety

The AI service may explain, detect and recommend. It must not independently:

- calculate or override statutory amounts;
- alter employee or salary records;
- approve Payroll Entry;
- submit a statutory return;
- invent a country rule.

Configure an external LLM only after reviewing your organisation's data
residency, retention and access requirements. The default explanation path is
deterministic and does not send payroll data outside ERPNext.
